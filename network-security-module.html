OSI & TCP/IP Models
Layers, PDUs, encapsulation, and why the model matters for security
Foundation

Why the OSI Model Matters for Security

The OSI (Open Systems Interconnection) model is a conceptual framework that standardizes how network communication works across seven layers. Security professionals use it to precisely locate vulnerabilities — a SQL injection is a Layer 7 attack, ARP spoofing is Layer 2, IP spoofing is Layer 3, SYN flood is Layer 4. When you know what layer an attack operates at, you know which controls to apply.

The TCP/IP model is the practical 4-layer implementation that the internet actually uses. In job interviews and real-world analysis, you'll reference both. OSI for precision, TCP/IP for implementation context.

💡 Memory trick: "All People Seem To Need Data Processing" (Application → Physical going down) or "Please Do Not Throw Sausage Pizza Away" (Physical → Application going up). Security tools map to layers — Wireshark = L2–L7, iptables = L3/L4, ModSecurity WAF = L7.

TCP/IP 4-Layer Model vs OSI

Application (TCP/IP) = OSI Layers 5+6+7. Transport (TCP/IP) = OSI Layer 4. Internet (TCP/IP) = OSI Layer 3. Network Access (TCP/IP) = OSI Layers 1+2. TCP/IP is what's actually implemented in software — OSI is the reference model for understanding and documentation.

Encapsulation — How Data Moves Down the Stack

Each layer wraps the layer above's data with its own header (and sometimes trailer). As data travels down the OSI stack from Application to Physical, each layer adds its header — this is encapsulation. The receiving end decapsulates from the bottom up, stripping headers at each layer.

Ethernet Header Src MAC + Dst MAC L2 · 14 bytes
IP Header Src IP + Dst IP L3 · 20 bytes
TCP Header Src Port + Dst Port L4 · 20 bytes
Payload Application Data L5–L7 · variable
Ethernet Trailer FCS L2 · 4 bytes

IP Addressing & Subnetting
IPv4, IPv6, CIDR notation, subnet math, and private address ranges
Core Knowledge

IPv4 Address Structure

An IPv4 address is 32 bits, written as four octets in dotted-decimal notation (e.g., 192.168.1.100). Each octet is 8 bits, range 0–255. The address has two parts: the network portion (identifies the subnet) and the host portion (identifies the specific device). The subnet mask (or CIDR prefix) separates these two parts.

Understanding subnetting is essential for network security: it determines which hosts are on the same segment, how broadcast traffic flows, and which routes packets take — all of which affect where you place firewalls, how you segment networks, and what traffic a VLAN can see.

Core Network Protocols
TCP, UDP, DNS, DHCP, HTTP/S, ARP, ICMP — how each works and where they're exploited
Protocols

TCP — Reliable, Connection-Oriented

TCP (Transmission Control Protocol) guarantees ordered, reliable delivery through a three-way handshake, sequence numbers, acknowledgements, and retransmission of lost packets. It's stateful — both sides maintain connection state. Used by HTTP/S, SSH, FTP, SMTP, databases — anything requiring guaranteed delivery.

TCP flags drive its state machine: SYN (initiate), ACK (acknowledge), FIN (graceful close), RST (abrupt reset), PSH (push data now), URG (urgent data). Security relevance: SYN without ACK response = SYN flood; RST injection = TCP session hijacking.

Client → Server
SYN
Seq=100, SYN=1. "I want to connect. My start seq is 100."
Server → Client
SYN-ACK
Seq=300, Ack=101, SYN=1, ACK=1. "OK, my start seq is 300."
Client → Server
ACK
Seq=101, Ack=301, ACK=1. "Confirmed. Connection open."
Both sides
DATA
Bidirectional data exchange with seq/ack tracking.
FIN / FIN-ACK
CLOSE
4-way FIN handshake to gracefully close the connection.

UDP — Fast, Connectionless

UDP (User Datagram Protocol) sends datagrams with no handshake, no acknowledgement, no guarantee of delivery or ordering. It's a fire-and-forget protocol — fast and efficient for latency-sensitive traffic where occasional loss is acceptable. Used by DNS queries, VoIP, online gaming, video streaming, NTP, DHCP, SNMP. Security: UDP amplification attacks exploit protocols with small requests producing large responses (DNS, NTP, SSDP).

DNS — The Internet's Phone Book

DNS (Domain Name System) translates human-readable hostnames (google.com) to IP addresses. It's hierarchical: Root servers → TLD nameservers (.com) → Authoritative nameservers (google.com's NS). Operates on UDP port 53 (queries) and TCP port 53 (zone transfers, large responses).

DNS record types every security analyst must know: A (hostname → IPv4), AAAA (hostname → IPv6), MX (mail server), CNAME (alias), NS (authoritative nameserver), TXT (SPF, DKIM, DMARC, domain verification), PTR (reverse lookup), SOA (zone authority info).

DHCP — Dynamic IP Assignment

DHCP (Dynamic Host Configuration Protocol) automatically assigns IP address, subnet mask, default gateway, DNS server, and lease time to hosts when they join the network. The DORA process: Discover (client broadcasts) → Offer (server offers IP) → Request (client requests offered IP) → Acknowledge (server confirms). Security: rogue DHCP servers can redirect all traffic by providing a malicious gateway.

ICMP — Diagnostics and Control

ICMP (Internet Control Message Protocol) is used for network diagnostics and error reporting. Ping uses ICMP Echo Request (Type 8) and Echo Reply (Type 0). Traceroute uses TTL manipulation — sends packets with TTL=1, 2, 3... each router decrements TTL; when it hits 0, the router sends ICMP Time Exceeded back, revealing the hop. Security: ICMP can carry data (covert channels), ping sweeps for host discovery, ICMP redirect attacks to modify routing.

Network Attacks
MITM, IP spoofing, TCP session hijacking, port scanning, and sniffing
Attacks

Network Attacks Target the Protocol Stack

Network attacks exploit weaknesses in protocol design and implementation — not application-layer vulnerabilities. Many core internet protocols (TCP, ARP, DNS, BGP) were designed for a trusted academic network and lack authentication entirely. Decades of security features have been bolted on — but legacy protocol weaknesses remain, especially inside corporate LANs.

MITM (Man-in-the-Middle) L2–L7 Intercept traffic between two parties by positioning self between them (ARP poison, DNS spoof, SSL strip) Credential theft, session hijacking, data modification ARP monitoring, HTTPS enforcement, cert pinning

ARP & DNS Attacks
ARP poisoning, DNS spoofing, DNS cache poisoning, and Kaminsky attack
Protocol Abuse

ARP — Unauthenticated by Design

ARP (Address Resolution Protocol) maps IP addresses to MAC addresses on a LAN. It has no authentication — any host can send an unsolicited ARP reply claiming "IP 192.168.1.1 is at MY MAC address." Hosts accept these and update their ARP cache. This is ARP spoofing / ARP poisoning — the most common LAN-based MITM attack.

Attack flow: Attacker sends ARP replies to victim saying "The gateway (192.168.1.1) is at my MAC." Attacker sends ARP replies to gateway saying "The victim (192.168.1.100) is at my MAC." All traffic between victim and gateway now flows through the attacker — classic MITM. Attacker forwards traffic transparently while reading/modifying it.

DNS Spoofing & Cache Poisoning

DNS spoofing tricks a resolver into caching a malicious IP for a domain. The famous Kaminsky attack (2008) showed that DNS's 16-bit transaction ID (65,536 possibilities) made it feasible to flood a resolver with forged responses, poisoning its cache. The fix: randomize source ports (65,536 × 65,536 = 4 billion combinations) and use DNSSEC.

DNS zone transfer abuse: AXFR (full zone transfer) dumps all DNS records for a domain. Should be restricted to authoritative nameservers only — if open, an attacker gets a complete map of all hostnames and IPs.

DoS & DDoS Attacks
SYN flood, UDP flood, amplification attacks, and botnet-based DDoS
Availability

Denial of Service — Overwhelming Resources

DoS (Denial of Service) attacks exhaust a target's resources — bandwidth, CPU, memory, connection tables — to prevent legitimate users from accessing the service. DDoS (Distributed DoS) uses thousands of compromised systems (botnet) to amplify the attack volume beyond what any single system could generate, and to make blocking by source IP infeasible.

DDoS attacks cost organizations an average of $40,000 per hour of downtime (Neustar). The largest recorded DDoS was 3.47 Tbps against Microsoft Azure in November 2021. Protection requires upstream mitigation — your server's bandwidth is simply overwhelmed before packets reach it.

Attack TypeLayerMechanismVolume PotentialMitigation
SYN Flood L4 Send millions of SYN packets with spoofed IPs. Server allocates half-open connection state for each, exhausting connection table (backlog queue fills) High — 100+ Gbps possible with botnet SYN cookies, rate limiting SYN packets, firewall connection limits
UDP Flood L4 Flood with UDP packets to random ports. Target sends ICMP Unreachable for each, consuming bandwidth and CPU Very high — stateless, easy to generate Rate limiting UDP, blackhole routing, upstream filtering
ICMP Flood (Ping Flood) L3 Flood with ICMP Echo requests. Target consumes bandwidth responding Moderate — ICMP often rate-limited Block ICMP at perimeter, rate-limit ICMP
DNS Amplification L4/L7 Send spoofed DNS queries (victim's IP) to open resolvers. Resolvers send large responses to victim. ~50× amplification factor Extremely high — amplification multiplies traffic BCP38 (block spoofed IPs), close open resolvers, DNSSEC
NTP Amplification L4/L7 monlist command in NTP returns last 600 clients — 206× amplification. Small query → huge response to victim Largest attacks reached 300+ Gbps Disable monlist (ntpd config), restrict NTP to authorized clients
HTTP Flood (L7) L7 Legitimate-looking GET/POST requests that bypass network-layer filtering. Target's web server / DB exhausted serving requests Moderate — hard to scale but hard to block WAF, rate limiting per IP/session, CAPTCHAs, CDN
Slowloris L7 Open many HTTP connections, send partial requests slowly — never completing. Exhausts server connection limit with minimal traffic Low traffic — single machine can DoS a server Connection timeout settings, max connections per IP, Nginx (not Apache)

Firewalls & Web Application Firewalls
Packet filters, stateful firewalls, NGFWs, iptables rules, WAF configuration
Defence

Firewall Types — Know All Four

Packet filter (L3/L4): Inspects each packet in isolation based on source/dest IP, port, protocol. Stateless — doesn't track connection state. Fast but limited — can't distinguish SYN from ACK flood, can't detect protocol abuse.

Stateful inspection (L4): Tracks connection state table. Allows return traffic automatically. Blocks packets that don't match established connections. Most modern firewalls. Vulnerable to state table exhaustion.

Application-layer / proxy (L7): Deep packet inspection at L7. Understands HTTP, DNS, FTP content. Can block by URL, user-agent, payload content. Slower but powerful. Used as reverse proxies.

NGFW (Next-Generation Firewall): Combines stateful + application awareness + IPS + SSL inspection + user identity (from AD). Can block specific applications (block Tor but allow HTTPS). Examples: Palo Alto, Fortinet, Check Point.

IDS & IPS
Snort rules, Suricata, signature vs anomaly detection, placement, and evasion
Detection

IDS vs IPS — Detection vs Prevention

IDS (Intrusion Detection System) monitors traffic, compares against signatures/baselines, and alerts when malicious activity is detected. It's passive — doesn't block anything. IPS (Intrusion Prevention System) is inline — traffic flows through it, and it actively drops malicious packets. IPS prevents attacks in real-time but can cause false-positive outages if misconfigured.

NIDS/NIPS
Network-based — monitor traffic at a network segment. See all traffic passing a chokepoint. Can't see encrypted traffic without SSL inspection. Deployed at DMZ, internet edge.
HIDS/HIPS
Host-based — agent on each endpoint. Monitors system calls, file changes, process creation, registry. Can see traffic after decryption. Wazuh, OSSEC are HIDS examples.
Signature-based
Match against known attack patterns (like AV signatures). Fast and accurate for known attacks. Zero-days and novel attacks evade signature detection entirely.
Anomaly-based
Establish baseline "normal" traffic, alert on deviations. Detects novel attacks. High false-positive rate — "unusual" is not always malicious. ML improves this significantly.
Snort
Most widely used open-source IDS/IPS. Rule-based, signature detection. Uses custom rule language. Active in enterprise and MSSP environments. Large rule community (Emerging Threats).
Suricata
Modern multi-threaded alternative to Snort. Snort-compatible rules + additional features. Built-in network metadata extraction, TLS fingerprinting (JA3), HTTP/DNS logging.

Secure Access

VPN — Encrypted Tunnel Over Untrusted Network

A VPN (Virtual Private Network) creates an encrypted tunnel between endpoints over an untrusted network (internet), making it appear as if they're on the same private network. Used for: remote worker access to corporate resources, site-to-site branch connectivity, and securing traffic over public Wi-Fi.

IPSec VPN operates at L3 (IP layer) — entire IP packets are encrypted and encapsulated. Two modes: Transport (encrypts payload only, original IP header preserved) and Tunnel (encrypts entire original packet, wraps in new IP header). Components: IKE (key exchange), AH (authentication), ESP (encryption + authentication).

Zero Trust — "Never Trust, Always Verify"

Zero Trust replaces the old "castle and moat" model (trust everything inside the perimeter). In Zero Trust: every access request is authenticated, authorized, and continuously validated regardless of whether it comes from inside or outside the network. Identity is the new perimeter.

Core principles: Verify explicitly — always authenticate and authorize. Least privilege access — only access what's needed. Assume breach — design as if the network is already compromised. Implemented via: MFA, conditional access, microsegmentation, device compliance checks, continuous monitoring.

ZTNA (Zero Trust Network Access) replaces VPN: users access specific applications (not the whole network), based on identity + device posture + location. Applications are never exposed to the internet — accessed only through a service broker. Examples: Cloudflare Access, Zscaler Private Access, Palo Alto Prisma Access.

Network Segmentation

Architecture

Why Segmentation Is Your Most Powerful Defence

Network segmentation divides a network into isolated zones, limiting lateral movement after a breach. If an attacker compromises a workstation in the user segment, segmentation prevents them from directly reaching database servers, financial systems, or backup infrastructure. Without segmentation, one compromised endpoint can pivot to compromise everything.

The principle: each segment should contain only systems that need to communicate with each other, with firewall/ACL enforcement between segments.

DMZ
Demilitarized Zone. Isolated segment for internet-facing services (web servers, email gateways, DNS). Two firewalls: internet-facing and internal-facing. Compromise of DMZ doesn't directly reach internal LAN.
VLANs
Virtual LANs segment at L2 using switch configuration. Tagged frames carry VLAN ID. Separate broadcast domains. VLAN 10: users, VLAN 20: servers, VLAN 30: management. Inter-VLAN routing via L3 switch or firewall.
Microsegmentation
Fine-grained segmentation at workload level — each VM/container in its own security zone. East-west firewall policies between individual workloads. Implemented with SDN, NSX, or cloud security groups.
Jump Server / Bastion
Single hardened host in DMZ used to access internal sensitive systems (servers, network devices). Admins connect to bastion first, then jump to internal targets. Provides audit trail and access control choke point.
Air Gap
Physical isolation — no network connection between segments. Used for: nuclear control systems, classified military networks, HSMs (Hardware Security Modules). Data transferred via physical media under strict controls.
NAC — Network Access Control
802.1X authentication at port level. Before a device gets network access, it authenticates (username+cert), compliance is checked (AV running? Patched?), and placed in appropriate VLAN based on identity/posture.

Wireless

Wireless Security Evolution

WEP (1997): RC4 stream cipher with static keys. Completely broken — crackable in under 60 seconds with aircrack-ng. Never use. WPA (2003): TKIP (Temporal Key Integrity Protocol). Better than WEP but TKIP is vulnerable. Legacy only. WPA2 (2004): AES-CCMP encryption. Secure when used with strong passphrases. WPA2-Personal (pre-shared key) vulnerable to offline dictionary attack on captured handshake. WPA2-Enterprise (802.1X/RADIUS) significantly more secure. WPA3 (2018): SAE (Simultaneous Authentication of Equals) replaces PSK — resistant to offline dictionary attacks. Forward secrecy. OWE for open networks. Required for Wi-Fi 6 devices.

Forensics

Network Forensics — Reconstructing What Happened

Network forensics is the capture, recording, and analysis of network traffic for the purposes of incident investigation, evidence gathering, and attack reconstruction. Unlike host forensics (examining disk/memory), network forensics works with packet captures, NetFlow records, firewall logs, IDS alerts, and DNS logs to reconstruct the attack timeline.

Key principle: collect first, analyze later. Traffic doesn't persist — if you don't capture it, it's gone. This is why perimeter packet capture (TAP or SPAN port) is essential infrastructure, not an afterthought.
