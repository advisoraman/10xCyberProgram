01
Why the Capstone Matters
A certificate says you studied. A capstone proves you can do the work.
Orientation

The Portfolio-Over-Certificate Reality

You've spent eleven weeks building labs, reports, scripts, and registers. Most candidates finish a course and walk away with only a certificate — a claim, not evidence. The capstone sprint is where you convert that claim into artifacts an interviewer can open, read, and question you on: a VAPT report with real CVSS scoring, a risk register with an actual heatmap, a SIEM deployment with your own detection logic.

In the Indian SOC/GRC/AppSec market at the L1–L2 level, this distinction is still rare. Most applicants list "CEH" or "Security+" on a resume with nothing to back it up. A public GitHub with 2–3 well-documented capstone deliverables puts you ahead of most of the applicant pool before the interview even starts.

What recruiters screen for
Keywords in your resume get you shortlisted. A linked portfolio gets you interviewed — recruiters skim GitHub links far more than they read bullet points.
What a capstone proves
That you can carry a security task end-to-end: scope it, execute it, document it professionally, and explain trade-offs — not just recognize terminology.
Why 2–3, not all 8
Depth beats breadth. Two deliverables you can defend in detail outperform five shallow ones with placeholder text and broken screenshots.
Why now
AI-assisted security workflows are new enough in 2025–26 that almost no other candidate will show them. Weeks 10–11 gave you that edge — the capstone is where you prove it.
💡 Interview edge: most 2025–26 security candidates can't explain prompt injection or demonstrate an AI-assisted VAPT workflow. Doing both during an interview — or showing them in your GitHub portfolio — immediately separates you from hundreds of applicants who only know traditional tools.

📄 Capstone Lab — Full VAPT Report on DVWA/WebGoat Technical ▶
  1. 1
    Scope and rules of engagement
    Write a one-page scope document: target (DVWA or WebGoat on your own lab VM), testing window, methodology (OWASP Testing Guide / PTES), and an explicit statement that this is a personal lab, not a live engagement.
  2. 2
    Execute and document each finding
    For every vulnerability (SQLi, XSS, IDOR, broken auth, etc.), capture: description, steps to reproduce with screenshots, CVSS 3.1 vector and score, business impact, and remediation guidance.
    Finding: SQL Injection — login form CVSS 3.1: AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:N → 9.1 Critical Impact: Full user table dump, credential exposure, potential auth bypass Reproduction: ' OR '1'='1 in username field, verified via sqlmap --batch --dbs Remediation: Parameterized queries / prepared statements; input validation; least-privilege DB account for the app
  3. 3
    Assemble the report
    Structure: Executive Summary (non-technical, 1 page) → Scope & Methodology → Findings sorted by CVSS severity → Remediation Roadmap (quick wins vs long-term) → Appendix (raw tool output). Export as PDF.
📊 Capstone Lab — DPDP Act Gap Assessment for an Indian SMB GRC · India ▶
  1. 1
    Define the fictional organization
    A 30–50 person Indian SMB (e.g. a D2C e-commerce brand or a healthtech app) that qualifies as a Data Fiduciary under the DPDP Act 2023. Write a one-paragraph profile: what personal data it collects, from whom, and why.
  2. 2
    Map obligations against current state
    Build a gap matrix across the DPDP obligations you covered in the GRC module: notice & consent, purpose limitation, data principal rights, breach notification (CERT-In 6-hour rule), Significant Data Fiduciary triggers, and cross-border transfer conditions.
    Obligation | Current State | Gap | Maturity (0–4) | Remediation | Owner | Priority
  3. 3
    Write the findings report
    Executive summary with an overall maturity score, top 5 priority gaps, a 90-day remediation roadmap, and an appendix with the full gap matrix. This is the single most-referenced deliverable in Indian GRC interviews.

Build Your GitHub Portfolio
The single link you'll paste into every application and every LinkedIn message
Portfolio

Repo Hygiene Is Part of the Deliverable

A GRC risk register with no README, or a VAPT report sitting alone with no context, reads as unfinished. Every capstone repo needs: a clear README explaining what it is and why you built it, tool versions used, embedded screenshots (not just links), and — for anything offensive-security related — an explicit legal/ethical disclaimer that testing was done only against your own lab environment.

    README.md template

SOC Interview Prep
Alert triage scenarios and MITRE ATT&CK are the two most-asked areas
Interview Prep
🎙️ Mock SOC Interview — Alert Triage Scenario Record Yourself ▶
Interviewer: You get an alert — a workstation made 200 DNS requests to random-looking subdomains in 60 seconds. Walk me through your triage. Strong answer: First, I'd check the alert severity and scope — is this one host or many? I'd pull the DNS logs to see the actual queried domains and check them against threat intel (VirusTotal, urlscan). Random-looking subdomains at high frequency strongly suggest DNS tunneling or a DGA-based C2 channel. I'd isolate the host from the network, check its process list and startup entries for the source process, and map the behavior to MITRE ATT&CK T1071.004 (DNS). Then I'd document the timeline, IOC list, and escalate per severity — this would be at least a P2 given possible active C2.

Record yourself answering out loud. Interviewers score structure (contain → investigate → document → escalate) as much as the technical answer itself.

GRC Interview Prep
Framework comparisons, risk scenarios, and audit walkthroughs
Interview Prep
🎙️ Mock GRC Interview — Four Questions to Rehearse Record Yourself ▶
  1. 1
    "Walk me through an ISO 27001 implementation plan for a startup."
    Structure your answer: define ISMS scope → conduct risk assessment → build risk treatment plan → select Annex A controls → draft the SoA → implement controls → internal audit → management review → certification audit. Mention typical timeline (6–12 months for a small org).
  2. 2
    "Explain a company's obligations under the DPDP Act 2023."
    Cover: notice and consent before processing, purpose limitation, data principal rights (access, correction, erasure, grievance redressal), reasonable security safeguards, and the CERT-In 6-hour breach notification requirement. Mention Significant Data Fiduciary obligations if the org is large-scale.
  3. 3
    "How would you build a risk register from scratch?"
    Identify assets → identify threats/vulnerabilities per asset → assess likelihood and impact → calculate risk score → decide treatment (accept/mitigate/transfer/avoid) → assign an owner and due date → track to closure. Reference your own capstone register as a live example.
  4. 4
    "What makes a good Statement of Applicability?"
    All 93 Annex A controls addressed, clear applicability justification for every exclusion, honest implementation status (not everything marked "done"), evidence references, and links back to specific risk register entries — not a generic template with no organizational context.
ISO 27001Certifiable

Angle: Management system standard — requires an ISMS, SoA, and continual improvement. Best answer: "It's a process framework, not a checklist — the SoA is the evidence trail."

NIST CSF 2.0Not certifiable

Angle: Outcome-based, US-origin, widely used for maturity self-assessment. Best answer: "Good for benchmarking maturity across Govern/Identify/Protect/Detect/Respond/Recover — often mapped to ISO 27001 controls."

DPDP Act 2023India · Legal

Angle: India's binding data protection law. Best answer: "Not optional like a framework — it's a legal obligation with financial penalties, enforced alongside CERT-In directions."

AI Security Interview Prep
The newest, least-competed area — prepare to stand out
Interview Prep

What Interviewers Are Starting to Ask

Very few 2025–26 candidates can explain prompt injection or the OWASP LLM Top 10, let alone show they've used AI tools inside an actual security workflow. Rehearsing these questions — and pointing to your AI Security capstone repo when you answer — is one of the highest-leverage things you can do this week.

Q: What is prompt injection?
An attack where untrusted input (a document, a webpage, a user message) manipulates an LLM into ignoring its instructions or leaking data — direct (in the user's own prompt) or indirect (hidden in content the model later reads).
Q: Name a few OWASP LLM Top 10 risks
Prompt injection, insecure output handling, training data poisoning, model denial of service, sensitive information disclosure, and excessive agency (an LLM given too much autonomous permission to act).
Q: How did you use AI tools in your labs?
Be specific and honest: which tasks you used Claude/MCP for (recon summarization, report drafting, policy generation) and which you did manually — interviewers probe for genuine hands-on understanding, not just tool-calling.
Q: What's "excessive agency" in an AI agent?
Giving an LLM-based agent more permissions or autonomy than the task needs — e.g. an AI assistant with unrestricted file-delete or send-email access — so a single manipulated output can cause real-world harm.
🤖 Bring the artifact, not just the answer: if you completed the LLM Threat Model capstone, walk the interviewer through your actual STRIDE table for the fictional chatbot — this converts a definitional answer into a demonstrated skill.

Technical rapid-fire questionWhat a strong answer covers
How does a TCP three-way handshake work?SYN → SYN-ACK → ACK; establishes sequence numbers and a reliable bidirectional connection before data transfer.
What is IDOR?Insecure Direct Object Reference — an app exposes an internal object reference (ID, file, key) without verifying the requester is authorized to access it.
Difference between IDS and IPS?IDS passively detects and alerts; IPS sits inline and can actively block or drop malicious traffic in real time.
How does bcrypt differ from MD5?bcrypt is a slow, salted, adaptive hashing algorithm built for passwords; MD5 is a fast general-purpose hash with known collisions — never suitable for password storage.
